# Processing pipeline

1. Validate tenant, document and version identifiers, source namespace and stage selection. Resolve bytes from trusted storage, bound the read and verify the optional digest. Validate file extension, declared MIME type, signature, readability, size and page limits.
2. Open a fresh immutable PDF or validated raster image. The parser registry selects the format implementation. Normalize image orientation and RGB mode. Bound rendering by DPI, maximum side and pixel count. Persist requested renders and addressable embedded PDF images with page associations.
3. Collect PDF text spans and page geometry. Character count, density, replacement-character rate and major image coverage determine the extraction path. Usable native text is retained. Poor text or scans trigger OCR. Mixed pages can OCR significant image regions without a matching text layer. Tesseract runs with configured languages, timeout, page segmentation, grayscale contrast correction, median filtering and optional mild deskew with boxes mapped back to source coordinates.
4. Preserve original per-page extraction JSON with bounding boxes, fonts, confidence, timestamp, native/scanned/mixed/image classification and quality signals. PDF coordinates are displayed page points and raster coordinates are oriented source pixels. Extract native ruled tables with PyMuPDF and retain row arrays, cell text, bounding boxes and readable text. Diagrams and charts retain a page image and available labels. Bitmap table structure and chart values require downstream interpretation.
5. Normalize Unicode, soft hyphen line breaks, whitespace and control characters. Matching headers and footers across selected pages are suppressed in normalized text. Tables are emitted atomically with IDs. Strategies are fixed character windows, overlapping windows, paragraph units, heading groups or page windows with word-boundary preference. All stay page-scoped and respect the target size except an indivisible table. Offsets index the stored normalized text in Unicode code points. Token counts use a lexical estimate.
6. Encode source chunks using the registered text model. Encode rendered images in bounded ColPali batches using its official processor. Preserve the full non-padding representation. Failed multi-page visual batches are isolated to individual pages. Candidate extraction sends identified passages to the configured provider, validates types and confidence and requires literal evidence. Token usage and prompt version travel with the candidates.
7. Write immutable content-addressed artifacts and stage receipts. The run digest includes source bytes, version identity, selected pages, stage and model configuration, pipeline version and caller idempotency key. Completed logical runs return the persisted success manifest. Partially failed runs retain attempt manifests. Identical retries resume successful checkpoints and reattempt missing stages. Downstream checkpoint keys incorporate input artifact checksums. Request ID and run ID serve different purposes.
8. Publish the final manifest after stage writes. Express schedules retries for transient failures. Object storage errors during manifest publication surface to the caller. A host crash can leave unreferenced content-addressed objects. Use a retention policy owned by the platform operator.

Low-confidence OCR and ambiguous reading order are explicit warnings. Blank pages can succeed with an empty extraction and a warning. Scanned table cells are not reconstructed from OCR. Changed processing configuration creates a new run. Keep source versions immutable upstream.
